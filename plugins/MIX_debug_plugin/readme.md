# MIX_debug_plugin — MIX 设备调试插件

MIX 设备的多通道 RPC 调试工具：批量管理设备连接、带自动补全的命令发送、
指令序列（命令/延迟/暂停）的编辑与执行、完整的操作日志。基于 PyQt6，
走 MIX_2.0 协议（ZeroMQ DEALER-ROUTER + JSON-RPC 2.0）。

- 入口：`MIX_debug_plugin.py`，类 `MIXDebugPlugin`，标签页名 `MIX_debug v4`
- 已在 `plugins/plugins.json` 注册，随主程序自动加载

## 一、界面与使用

```
┌──────────────┬──────────────────────────────────────────────┐
│ 通道列表      │  命令输入(自动补全) + 参数输入     [发送]       │
│ IP/端口/状态  ├──────────────────────────────────────────────┤
│ [连接][断开]  │  历史指令（双击重发，右键：清空/添加到序列/删除）│
│              ├──────────────────────────────────────────────┤
│              │  指令序列（组 → [CMD]/[DELAY]/[PAUSE]）  [执行] │
├──────────────┴──────────────────────────────────────────────┤
│ 日志（总日志 + 各通道独立页签，右键清空当前/全部）               │
└─────────────────────────────────────────────────────────────┘
```

### 1. 通道管理

- 右键通道列表 → **新增一行**（单个添加）或**配置通道**（批量生成：
  通道数量、起始 IP、起始端口、端口递增步长）
- 逐行**连接 / 断开**，或右键**批量连接 / 批量断开**选中通道
- 连接成功后自动获取设备支持的服务与命令列表
- 通道配置自动保存，下次启动自动恢复

### 2. 发送命令

1. 命令输入框有**自动补全**（`QCompleter`，数据来自设备实际命令列表）
2. 参数框填参数（如 `channel=1 count=100`）
3. 点**发送** → 发到所有已连接通道，各通道响应分别写进日志

### 3. 指令序列

序列是两层树：**序列组 → 子指令**，子指令三种类型：

| 前缀 | 含义 | 来源 |
|---|---|---|
| `[CMD]` | 一条 RPC 命令 | 历史指令右键「添加到序列」/ 序列右键「添加指令」 |
| `[DELAY]` | 延迟等待（1–30000ms） | 序列右键「添加延迟」 |
| `[PAUSE]` | 暂停，弹框等用户确认 | 序列右键「添加暂停」 |

操作要点：

- **勾选即生效**：组/子指令的勾选状态决定执行范围；勾选组会级联子指令
- 调整顺序用右键**上移 / 下移**（不支持拖拽）
- **执行序列**：按顺序只跑「已勾选组里已勾选的项」；延迟用定时器实现，
  执行中可随时停止
- **自动保存**：任何修改（增删改、移动、重命名）后自动落盘；空组不落盘
- **持久化为 CSV**：每个组一个文件（组名即文件名），支持保存当前组 /
  保存全部 / 加载 / 用系统默认程序打开最近编辑的 CSV
- **启动自动加载**：扫描配置目录下所有序列组 CSV，未加载的自动加入
  （默认折叠，同名跳过）
- 一个序列都没有时，「添加指令/延迟/暂停」会自动静默新建「默认序列组」，
  不会失败

### 4. 历史指令

- 已发送的命令自动进历史（去重，**最多保留 50 条**），随配置持久化
- **双击**历史项 = 填入命令框并立即发送
- 右键：清空所有 / 添加到序列 / 删除单条

## 二、文件结构

```
MIX_debug_plugin/
├── MIX_debug_plugin.py      # 主插件（界面 + 通道/历史/序列/日志逻辑）
├── MIX_debug_plugin.ui      # Qt Designer 界面文件
```

每个通道一个实例）→ `mix8_rpc_client.py`（协议实现）。

## 三、RPC 通信要点

- **传输**：ZeroMQ DEALER 套接字，消息为 JSON-RPC 2.0 格式
- **注册流程**：连接后自动注册到服务器（version → hello → get_all_services），
  失败自动重试（最多 3 次）；注册成功后才能调用该设备的命令
- **服务发现**：连接时拉取服务与命令列表，同时刷新命令补全
- **心跳**：客户端带心跳检测，异常断开会在通道状态与日志中体现

协议细节（注册时序、客户端 ID 规则、错误码、故障排除）见
[mix/readme.md](mix/readme.md)。

## 四、配置与数据文件

用户数据都在 `~/.MIX-Tool/`（Windows 为 `%APPDATA%/MIX-Tool/`）：

| 文件 | 内容 | 谁写 |
|---|---|---|
| `config.json` | 通道列表、历史指令等 | 主插件（经 `utils.config.config_manager`） |
| `commands_info.json` | 最近一次获取的设备命令表 | 连接成功时 |
| `序列组名.csv` | 每个序列组一个文件 | 序列增删改时自动 / 手动保存 |

序列组 CSV 行格式：`类型,内容,勾选`，类型 ∈ `CMD / DELAY / PAUSE`
（`DELAY` 的内容为毫秒数），可直接用表格软件编辑。

## 五、开发与测试

### 用模拟服务器调试（无需真机）

```bash
# 启动模拟服务器（power/relay/baseboard 三个模拟服务）
bash plugins/MIX_debug_plugin/mix/mix8_rpc_server.sh

# 模拟注册失败场景（测试客户端重试逻辑）
bash plugins/MIX_debug_plugin/mix/mix8_rpc_server.sh --test-reg-fail
```

脚本会先关闭占用 7801 端口的旧进程再启动。通道里填 `127.0.0.1:7801` 即可联调。

### 添加新模拟服务

在 `mix/mix8_rpc_server.py` 中加服务类并注册：

```python
class NewService:
    def new_method(self, param1, param2):
        """新方法的文档（会出现在命令提示里）"""
        return {"result": "success"}

self.register_service("new_service", NewService())
```

### 改协议格式

RPC 消息格式集中在 `mix/mix8_rpc_client.py`，按设备要求调整即可。

## 注意事项

1. 命令能被补全的前提是**至少连接过一次**设备（命令表来自设备实报，
   并缓存到 `commands_info.json`）
2. 部分命令要求设备侧已完成注册，否则服务器会拒绝
3. 执行序列期间 UI 线程会被延迟/暂停占用，超长延迟建议拆分成多组
4. 序列组按组名落盘为 CSV：**重命名组会生成新文件**，旧 CSV 需手动清理
